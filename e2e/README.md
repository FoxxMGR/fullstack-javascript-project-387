# Интеграционные (e2e) тесты

Проверка приложения на уровне пользовательских сценариев в **реальном браузере**
с помощью **Playwright**. Тесты покрывают основной путь бронирования целиком:
фронтенд ↔ прокси Vite ↔ бэкенд.

## Как это работает

`playwright.config.ts` через `webServer` сам поднимает перед прогоном:

1. бэкенд — `npm --prefix ../server start` (`http://localhost:8080`);
2. фронтенд — Vite dev (`http://localhost:5173`), который проксирует
   `/guest` и `/admin` на бэкенд.

Таким образом каждый тест реально прогоняет связку «фронтенд + бэкенд» и
проверяет результат на экране браузера.

## Установка

```bash
cd e2e
npm install
npx playwright install chromium   # один раз, скачивает браузер
```

## Запуск

```bash
npm test                # headless, все тесты
npm run test:headed     # с видимым окном браузера
npm run report          # открыть HTML-отчёт (после CI-артефакта)
```

Первый запуск поднимет оба сервера автоматически. Чтобы не наткнуться на уже
запущенные вручную серверы — остановите их или удалите флаг reuse. В CI
(`reuseExistingServer: false`) всегда поднимаются свежие процессы.

## Что покрыто

- **Основной сценарий бронирования** (`tests/booking.spec.ts`):
  гость → тип события → свободный слот → форма → подтверждение; владелец видит
  бронь; после записи занятый слот исчезает из выбора.
- **Тип события владельца** (`tests/booking.spec.ts`): владелец создаёт тип —
  гость видит его и записывается.
- **Занятый слот** (`tests/conflict.spec.ts`): дважды забронировать один слот
  нельзя — второй запрос получает `409 SLOT_UNAVAILABLE`, слот уходит из списка.

## CI

Тесты запускаются в GitHub Actions: `.github/workflows/e2e.yml`
(производит `server`, `web`, `e2e`, ставит браузер chromium и запускает
`npx playwright test`). Отчёт загружается артефактом при падении.
