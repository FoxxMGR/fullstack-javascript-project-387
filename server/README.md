# Бэкенд (server)

Серверная часть приложения «Календарь встреч», реализованная **по контракту**
из `api-spec/main.tsp` (TypeSpec → OpenAPI, см. `api-spec/tsp-output/`).

API предназначен для отдельного фронтенд-клиента (`web/`). В dev-режиме Vite
проксирует пути `/guest/*` и `/admin/*` на этот бэкенд.

## Стек

- **Node.js ≥ 23.6** (нативная поддержка TypeScript, запуск без сборки)
- Встроенный модуль `node:http` — **без внешних runtime-зависимостей**
- Хранилище **в памяти**: после перезапуска сервиса данные сбрасываются

## Установка и запуск

```bash
npm install        # только devDependencies: typescript, @types/node
npm start          # http://localhost:8080
npm run dev        # с автоперезапуском при изменении файлов (node --watch)
```

Порт можно сменить переменной окружения: `PORT=9000 npm start`
(фронтенд по умолчанию ожидает бэкенд на `:8080`, см. `web/vite.config.ts`).

## API (контракт)

| Метод  | Путь                    | Описание                                  |
| ------ | ----------------------- | ----------------------------------------- |
| GET    | `/health`               | Служебный статус сервиса                  |
| GET    | `/guest/event-types`    | Доступные типы событий                    |
| GET    | `/guest/availability`   | Слоты для типа события (`eventTypeId`, `dateFrom?`, `dateTo?`) |
| POST   | `/guest/bookings`       | Создать бронирование (`CreateBookingRequest`) |
| POST   | `/admin/event-types`    | Создать тип события (`CreateEventTypeRequest`) |
| GET    | `/admin/event-types`    | Все типы событий (для управления)         |
| GET    | `/admin/bookings`       | Бронирования (`from?`, `to?`, `status=upcoming\|past`) |
| DELETE | `/admin/bookings/{id}`  | Отменить бронирование                     |

Ошибки возвращаются в формате `ValidationError` из контракта
(`{ code, message, details? }`) с соответствующим HTTP-статусом
(400 — невалидные данные, 404 — не найдено, 409 — слот занят, 413 — тело
слишком большое).

## Бизнес-правила

- Слоты генерируются по рабочему окну владельца: **Пн–Пт, 09:00–18:00**
  (локальное время сервера), шаг сетки = длительность типа события.
- Слот считается **занятым**, если пересекается с любым существующим
  бронированием (по всему календарю, а не только по типу события — владелец
  не может находиться на двух встречах одновременно).
- Создание бронирования проверяет: существование типа события, валидность
  полей, будущее время, попадание в сетку рабочего времени и отсутствие
  пересечений. При попытке занять уже занятый слот возвращается
  `409 SLOT_UNAVAILABLE`.
- Отмена бронирования освобождает слот: слот снова появляется в
  `/guest/availability` со значением `isAvailable: true`.

## Структура

```
src/
  server.ts      — входная точка, запуск HTTP-сервера
  app.ts         — маршрутизация и обработчики контрактных путей
  store.ts       — in-memory хранилище и демо-данные
  slots.ts       — генерация сетки слотов и правила занятости
  validation.ts  — валидация полей по ограничениям контракта
  errors.ts      — ApiError → ValidationError
  types.ts       — модели данных по контракту
```

## Проверка типов

```bash
npm run check    # tsc --noEmit
```

## Примеры запросов (curl)

```bash
# Слоти для типа события на следующую неделю
curl "http://localhost:8080/guest/availability?eventTypeId=<id>&dateFrom=2026-09-01&dateTo=2026-09-05"

# Создать бронирование
curl -X POST http://localhost:8080/guest/bookings \
  -H 'Content-Type: application/json' \
  -d '{"eventTypeId":"<id>","guestName":"Иван","guestEmail":"ivan@example.org","startTime":"2026-09-01T09:00:00+03:00"}'
```
