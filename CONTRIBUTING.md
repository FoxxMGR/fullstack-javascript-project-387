# Соглашение о коммитах (Conventional Commits)

В проекте принят формат сообщений коммитов по спецификации
[Conventional Commits](https://www.conventionalcommits.org/). Он используется
автоматизацией релизов: **release-it** (запускается в GitHub Actions на каждый
push в `main`) анализирует коммиты и автоматически публикует новую версию:
обновляет `CHANGELOG.md`, ставит тег и создаёт GitHub Release по правилам
семантического версионирования.

## Формат

```
<type>(<scope>): <краткое описание>
```

- `<type>` — обязателен, отвечает за классификацию изменения (и, при выпуске,
  влияет на номер версии).
- `<scope>` — необязательная область (сервис/модуль), удобно использовать
  `server`, `web`, `e2e`, `ci`, `deps`.
- Описание — краткий заголовок в форме повелительного наклонения
  («добавляет…», «исправляет…», «настраивает…»).

### Типы

| Тип        | Что означает                                         | Версия |
| ---------- | ---------------------------------------------------- | ------ |
| `feat:`    | Новая функциональность                                | minor  |
| `fix:`     | Исправление ошибки                                    | patch  |
| `perf:`    | Оптимизация производительности                        | patch  |
| `docs:`    | Изменения только в документации                       | —      |
| `refactor:`| Изменения без изменения поведения                     | —      |
| `test:`    | Добавление/изменение тестов                           | —      |
| `ci:`      | Изменения в CI/CD-конфигурации (GitHub Actions и т.п.)| —      |
| `chore:`   | Обслуживание, вспомогательные изменения               | —      |
| `build:`   | Изменения в системе сборки/зависимостях               | —      |

## Примеры

```
feat(server): добавить эндпоинт отмены бронирования
fix(web): не показывать занятый слот в списке доступных
refactor(server): выделить генерацию слотов в отдельный модуль
ci: добавить запуск e2e-тестов в GitHub Actions
docs: описать команду работы с коммитами
```

## Обязательное для агента

Все коммиты, которые создаёт агент (ассистент разработчика), обязаны
соответствовать этому формату. Перед фиксацией выбирается корректный
`<type>`, а область (`<scope>`) уточняет подмодуль, если это уместно.

## Нарушения

Изменение в CHANGELOG и нумерация версий зависят только от корректных
заголовков коммитов, попавших в `main`. Не следует использовать free-form
заголовки — они не попадут в changelog релиза.

Для локального контроля заголовков установлен `commitlint`
(конфигурация в `commitlint.config.cjs`); можно выполнять проверку вручную или
в пре-коммит-хуке.
